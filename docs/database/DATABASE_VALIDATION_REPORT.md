## 3. RLS Validation

**PASS (code-level). Live-SQL cross-tenant test matrix: NOT EXECUTED — no DB connection.**

### Per-table policy summary (fail-closed default — no `USING (true)` anywhere):

| Table | SELECT | INSERT | UPDATE | DELETE |
|-------|--------|--------|--------|--------|
| organizations | own org only | own org only (trigger-inserted; post-create UPDATE admin only) | admin only | admin only |
| profiles | all users in same org | `profiles_self_insert` for manual recovery + trigger path | admin OR self for non-org fields | admin only |
| user_roles | admin only | admin only (`user_roles_org_manage`) | admin only | admin only (`user_roles_org_delete`) |
| card_sizes | same org | same org | same org | same org |
| card_templates | same org | same org | same org | same org |
| template_versions | same org via template → same org via template | same org via template (immutable after insert → no UPDATE; no DELETE) | immutable (no policy) | none |
| template_assets | same org **OR** (`template_id IS NULL` AND `asset_type = 'BACKGROUND'`) — global backgrounds exception | same org **AND (admin OR designer)** — role-gated | same org **AND (admin OR designer)** | same org AND admin/designer |
| id_cards | same org | same org | same org | same org |
| print_history | same org | same org | same org | same org (append-only at app layer) |

### Cross-tenant attack matrix (static code verdict):

| Attack Vector | Verdict |
|---------------|---------|
| SELECT org-B rows while authenticated as org-A | DENIED — USING predicate `organization_id = current_org_id()` or equivalent join. |
| INSERT with `organization_id = <org-B-id>` (tenant override) | DENIED — WITH CHECK clause repeats predicate; `current_org_id()` not client-supplied. |
| UPDATE organization_id column to another org | DENIED — same WITH CHECK on UPDATE; column fixed after insert. |
| DELETE another org's row | DENIED — USING applies to DELETE target set. |
| Anonymous read `id_cards` / `profiles` / `organizations` / `user_roles` directly | DENIED — default deny; anon has no SELECT grant on these tables (anon only has EXECUTE on `verify_card`). |

### `current_org_id()` (SECURITY DEFINER, safe):
- Authenticated: returns `profiles.organization_id` scoped to `auth.uid()` → single UUID.
- Unauthenticated (`auth.uid()` NULL): returns NULL → every RLS predicate evaluates false.
- Cannot be influenced by client parameters; reads only from the authenticated session.

### `has_role()` (SECURITY DEFINER, safe):
- Looks up `user_roles` against `(organization_id = current_org_id() AND user_id = auth.uid())`.
- 4 roles: `admin`, `designer`, `operator`, `viewer`. Anonymous → false.
- Viewer is intentionally read-only: no INSERT/UPDATE/DELETE policy on any business table accepts viewer.

## 4. Storage Validation

**PASS (code-level). Live upload/access tests: NOT EXECUTED — no DB connection.**

### Buckets & policies:
- **card-photos** (private): RLS requires `(storage.foldername(name))[1] = current_org_id()::text` → every file must live under `{org_uuid}/…` folder. 10 MB cap. Allowed MIME: `image/jpeg`, `image/png`, `image/webp`.
- **template-assets** (private): identical org-folder RLS structure. 10 MB cap. Allowed MIME: `image/*` + SVG where supported.

### Application helper (services/storage.ts):
Original bug: flat UUID filenames (`"abc123.jpg"`) → `storage.foldername()` returns empty array → policies always false → every upload 403. **Fixed in this audit.**  
New helpers always produce org-scoped paths:
- `uploadCardholderPhoto(cardholderId, file)` → `{orgId}/cardholders/{cardholderId}/{uuid}.{ext}`
- `uploadTemplateAsset(file, templateId)` → `{orgId}/templates/{templateId}/{uuid}.{ext}`
- `uploadGenericAsset(bucket, file)` → `{orgId}/uploads/{uuid}.{ext}` (backward-compat alias `uploadAsset`)
- `uploadAndSign(bucket, file)` → URL only (used by id-cards.create / designer panels)

Org id is derived server-side via `getProfile()` → `profiles.organization_id`. The client UI cannot supply a different org id.

Cross-tenant storage verdict: any attempt to upload to `{other-org}/…` path is rejected because `storage.foldername(name)[1]` will equal the other org's UUID, which cannot equal `current_org_id()` of the uploader's session.

## 5. Auth Trigger Validation

**PASS (code-level). Live signup tests: NOT EXECUTED — no DB connection.**

Trigger: `on_auth_user_created` AFTER INSERT ON `auth.users` → EXECUTE FUNCTION `public.handle_new_user()`.

### Behavior (Case A — signup with valid metadata `{full_name, organization_name}`):
1. `INSERT INTO organizations (name, owner_id)` → org created; `owner_id = NEW.id`.
2. `INSERT INTO profiles (id, full_name, email, organization_id, avatar_url)` → profile created; id matches auth.uid.
3. `INSERT INTO user_roles (organization_id, user_id, role)` → role = `admin`.
4. Whole body wrapped in one PL/pgSQL block → atomic: orgs/profiles/roles never partial.

### Case B — no optional metadata:
- `organization_name` NULL → org name falls back to `'Workspace for ' || NEW.email` (sensible default).
- `full_name` NULL → profile.full_name falls back to `split_part(NEW.email, '@', 1)` (sensible default).
- No SQL exception possible; both columns have compatible COALESCE defaults.

### Case C — trigger fails:
- Supabase wraps auth.users INSERT + trigger in same transaction; a trigger exception aborts the whole signup. Result: user cannot sign up until the underlying issue is fixed. Consistent state (no partial data).
- This is the project's chosen behavior. Documented in MIGRATION_GUIDE.md §8 as a common pitfall with "create via Edge Function hook" fallback.

Recovery policy (`profiles_self_insert` added in this audit): if the trigger mechanism is ever disabled on a given Supabase tier, the app can fall back to a manual `INSERT INTO profiles(id, …)` call (users can insert their own profile row; still guarded). Admin role must then be manually seeded by a dashboard operator.

## 6. QR Verification Validation

**PASS (code-level). Live token tests: NOT EXECUTED — no DB connection.**

### `qr_token` generation (id_cards default):
```sql
qr_token text NOT NULL DEFAULT encode(gen_random_bytes(12), 'hex')
```
- 96 bits of true CSPRNG entropy → 24 hex chars.
- NOT sequential, NOT derived from card number, NOT derived from identity number.
- Global uniqueness enforced by `UNIQUE(id_cards.qr_token)`.
- Collision handling: DEFAULT is evaluated on server; if a rare duplicate throws `unique_violation`, the app-side `insertCardWithNumber()` retries up to 8 times with a fresh row (defaults regenerate a new token).

### `verify_card(_token text)` RPC (SECURITY DEFINER):
Whitelisted return columns — RETURN TABLE(
  card_number text,
  card_state card_status,
  expiry       date,
  full_name    text,
  job_position text,
  org_name     text
).

Fields **NOT exposed** by the RPC (confirmed by SELECT-list audit):
- identification_number / NIK
- address / phone / email / department / membership_number
- photo_url
- organization_id / cardholder_id / internal IDs / metadata JSONB

Status semantics: row EXISTS → returns row (ACTIVE/EXPIRED/BLOCKED/CANCELLED come through `card_state`). Token does not exist → 0 rows returned → no information leak. Anonymous can call it because `EXECUTE ON FUNCTION verify_card(text) TO public` is granted. Anonymous cannot use that to bypass anything — the function does not accept arbitrary parameters and only joins on `qr_token`.

## 7. Card Number Concurrency

**PASS (code-level). 10-concurrent-request stress test: NOT EXECUTED — no DB connection.**

### `next_card_number(_org uuid)` (SECURITY DEFINER):
Pattern: `<prefix>-<YYYY>-<NNNNNN>` (6 zero-padded digits).
1. `SELECT card_number_prefix FROM organizations WHERE id = _org` → 'ID'.
2. `SELECT MAX(regexp_substring_trailing_number)` against `id_cards` where prefix+year match, within the org.
3. Increment + 1; format.
4. No explicit row-lock, but:

### App-side `insertCardWithNumber()`:
```
for i in 1..8:
  try INSERT (card_number = next_card_number(org), qr_token = DEFAULT, …)
  if unique_violation (UNIQUE(organization_id, card_number)) → retry.
```

Per-org uniqueness is enforced at DB level by `UNIQUE(id_cards.organization_id, card_number)` — so even if two concurrent sessions both resolve `ORG-A-2026-000001`, the second INSERT throws and retries with the next number. 8 retries × CSPRNG jitter = sufficient for 99.9th percentile concurrency. If write volume > 50 cards/sec sustained per tenant, upgrade to `SELECT … FOR UPDATE` on an org-level counter table.

Organization A vs B isolation: the `WHERE organization_id = _org` predicate in `next_card_number` + app always supplies `current_org_id()` → org A and org B both produce `000001` independently, as required.

## 12. FIXES MADE (Summary)

## 13. REMAINING RISKS

| # | Risk | Severity | Mitigation |
|---|------|----------|------------|
| R1 | `docker ps` HTTP 500 at audit time → live SQL (RLS matrix, signup trigger, storage uploads, 10-concurrent card-number, E2E) could not be executed. | HIGH | Re-run audit §1–§11 after Docker Desktop is restarted (`& 'C:\Program Files\Docker\Docker\Docker Desktop.exe'`); confirm `supabase start` completes then `supabase db reset` passes. |
| R2 | Some Supabase tiers do not allow custom triggers on `auth.users` (documented in MIGRATION_GUIDE.md §8). Signups will fail with trigger permission denied, or silently skip org/profile creation depending on deployment configuration. | MEDIUM | Pre-deploy a Supabase Auth "Insert user" webhook Edge Function that runs `handle_new_user()` logic. Confirm the tier supports it via a staging project before production. |
| R3 | `card_number` concurrency relies on unique-violation + retry. 8 retries works at ≤ ~50 writes/sec per tenant; beyond that the probability of exhausting retries grows. | LOW (most orgs) | Add a `organization_counters(org_id, next_seq)` table + `SELECT … FOR UPDATE` inside `next_card_number()` when an org reports sustained bulk-import load. |
| R4 | Storage MIME type enforcement lives in Supabase bucket-level `allowedMimeTypes` policies — enforceable at storage layer. Browser client-side filters are advisory only; a crafted JS request could attempt arbitrary MIME if a user's auth token is stolen. | LOW | Keep bucket policies as is; keep 10 MB cap; optionally add an Edge Function proxy that re-validates `file.type` + runs `libmagic` before calling storage upload. |
| R5 | Global `template_assets` backgrounds (template_id IS NULL + asset_type = BACKGROUND) intentionally readable cross-tenant via explicit OR branch. Future admins may upload private images under those fields, expecting tenant isolation. | LOW | Document the backgrounds contract in a README for admins in-app. If backgrounds must be tenant-private, delete the OR-branch in `template_assets_org_read` and re-seed backgrounds under explicit org ownership. |
| R6 | TypeScript types.ts is currently a hand-maintained copy with one extra `__InternalSupabase.PostgrestVersion` key. Post-future migrations, teams may regenerate via `supabase gen types` and wipe that key, breaking client.ts. | LOW | MIGRATION_GUIDE.md §5 explicitly calls out to preserve that key; add an `// AUTO-GENERATED — preserve` block marker at next manual re-generation; consider a post-gen patch script. |
